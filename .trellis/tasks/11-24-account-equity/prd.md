# 子任务 7：账户权益与本金（account-equity）

## Goal

把账户读数改到与 Gate 统一账户的真实口径一致：本金取钱包总额
（`GET /wallet/total_balance` 的 `total.amount − total.borrowed`），可用于合约的额度取合约账户的 `available`，
权益 = 本金 + 未实现盈亏。本金、权益、可用于合约的额度、初始资金在代码里各只有一处定义。
初始资金在创建 trader 时取当时的本金，界面可编辑，存量无效值在加载时以当前本金重建。
删除「以合约账户的 `total` 作钱包余额」的旧口径。

## Requirements

父任务：`11-24-gate-trading-foundation`（Gate 交易基座）。需求与决策以父分支
`docs/plans/2026-11-24-gate-trading-foundation.zh-CN.md` 为准；本文件是该子任务在计划文档第 10.2 节第 7 行
与第 8.2 节删除清单的落地。依赖子任务 1（SDK v7.2.184），以及子任务 4 已合父（恢复开仓能力排在开仓路径加固之后），
两者都已满足。

### 背景

- **权益为 0 的根因**（计划文档第 1 节、3.1 节、8.2 节）：`trader/gate/trader_account.go` 的 `GetBalance` 把
  `GET /futures/usdt/accounts` 的 `total` 当作钱包余额。文档写明 `total`「只适用于经典合约账户」，统一账户下恒为 0，
  于是权益 ≈ 0、单仓上限为 0、提示词里的权益与可用余额都是 0。
- **初始资金被记成 0**：创建 trader 时后端用交易所读数覆盖用户输入（`api/handler_trader.go`），读数走
  `totalWalletBalance`，在 Gate 上得到 0；加载时 `trader/auto_trader.go` 发现初始资金不大于 0 会重新取数，
  但键名列表在 Gate 上同样取到 0。界面没有初始资金的编辑入口，只有一条「系统将自动获取您的账户净值作为初始余额」的提示。
- **口径散落**：同一组键名与「权益 = 钱包余额 + 未实现盈亏」的公式在交易路径（决策上下文、账户信息、开仓、网格两处）、
  API（创建、同步余额、账户状态）与助手（创建 trader）各写了一遍。
- **账户现状**（2026-11-24 只读实测）：无持仓、无挂单、无条件单；`total.amount = 107.49769421`、`total.borrowed = 0`、
  `total.unrealised_pnl = 0`；合约账户 `total ≈ 0`、`available = 107.49769`；保证金模式仍是跨币种，持仓模式为单向。

### 范围

1. **Gate 取数**：`GetBalance` 的本金、未实现盈亏取自钱包总额，可用于合约的额度取自合约账户；
   钱包总额里必然存在的字段缺失或解析失败即报错。
2. **口径只定义一处**：本金、未实现盈亏、可用于合约的额度、权益、初始资金各有一个定义，交易路径、API 与助手都用它；
   删除散落的键名列表与公式。
3. **初始资金**：创建 trader 时取当时的本金；存量无效值（不大于 0）在加载时以当前本金重建、写回数据库并记录日志；
   读不到本金或本金不为正时加载失败并说明是哪一种原因（原因按错误类型识别，不靠匹配文案）；
   更新接口对负值返回错误；换绑交易所时旧的初始余额重置、加载时以新账户的本金重建（页面、REST、助手三条路径一致）。
4. **界面**：编辑 trader 的表单可以修改初始资金，非正值不能保存，只有改过才随保存发送；创建表单的提示改为新口径；
   中文、英文、印尼文三种文案同步。
5. **文档与规格**：`docs/pnl.md` 的初始资金口径；后端规格新增账户读数的契约；计划文档回写实测发现与实施进度。

### 约束

- 适配层只做「外部接口 ↔ 规范单位」的换算与校验，不含交易判断（父任务 design.md）。
- 外部数据解析失败即报错，不回落猜测值（父任务 design.md 约定 3）。
- 其他交易所的适配器不改取数逻辑（D3）：它们仍然返回 `totalWalletBalance`、`totalUnrealizedProfit`、`availableBalance`。
  权益取值的规则对全部交易所相同：适配器直接报告了权益（`totalEquity` / `total_equity`）时用它，否则用钱包余额加未实现盈亏。
  例外是 OKX 适配器补了一个键 `totalEquity`（一行）：它把权益放在 `totalWalletBalance` 里，不补的话权益会多算一次未实现盈亏，
  开仓上限也会因此比改动前多算。这条规则带来的取值变化（开仓上限与网格对没有 `totalEquity` 的适配器改用权益、
  设置页三个交易所的显示值从钱包余额变为权益）写在 design.md 里
- 初始资金取本金对全部交易所一致（计划文档第 5 节）。对直接报告权益的交易所（bybit、bitget、kucoin、lighter），
  创建与同步时记录的值从权益变为本金；两者只在账户当时有浮动盈亏时不同。
- 不启动 trader、不激活策略（D20）。
- 带仓读数需要账户里有仓位：沿用 W3（ETH_USDT 0.1 张，约 1.7 USDT，随单保护，读数后立即平仓），在 D35 的授权范围内
  （单笔名义价值不超过 10 USDT、每一步完成后立即还原）；开仓请求带上该合约现有的保证金模式与杠杆，不改动账户的仓位设置。
- 提示词的金额契约（去掉金额字段、按本金百分比计算）属于子任务 9，本子任务不改提示词文本。

### 真实验证对设计的修正（2026-11-24）

详见 `research/gate-account-balance-docs.md` H 节与 `probe/README.md`：

- 开仓那一刻本金下降的正是手续费：本金不随**未实现**盈亏变动，但手续费与已实现盈亏是即时结算的
- 钱包总额的 `total.unrealised_pnl` 没有可见的缓存滞后，权益按计划文档取它
- 「可用额度 = 本金 + 未实现盈亏 − 头寸占用保证金」不严格成立，交易所内部的计算方式没有文档
