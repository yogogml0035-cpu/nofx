# 子任务 ⑩：分批平仓（partial-close）

## Goal

模型可以在决策里按比例分批平仓。系统按合约最小步长精确换算平仓张数，提交 reduce-only 市价单；
提示词里的持仓信息逐仓标明能否分批；比例 100%（等同全平）、换算后不足一个最小步长、持仓不是
步长整数倍、适配器不支持精确换算时一律拒绝，不产生交易所调用。

## Requirements

1. **决策契约**
   - 新增动作 `close_long_partial`、`close_short_partial`，新增字段 `close_percent`（百分数）。
   - 只对已有对应方向持仓发起；比例必须为有限正数且 `< 100`。`100` 表示全平，必须走既有
     `close_long`/`close_short`；分批动作收到 `100` 时拒绝并指出应使用的全平动作。
   - 动作与比例的解析、校验在 AI 响应解析阶段完成；非法动作或比例在任何交易所调用前拒绝。
   - 既有 `close_long`/`close_short`（全平）语义不变。

2. **持仓可分批标记**
   - 每轮提示词的“当前持仓”逐仓标明能否分批。
   - 能分批当且仅当：适配器实现精确分批能力，交易所可读到持仓张数与最小步长，且持仓张数
     严格大于一个最小步长（至少两步）。
   - 适配器不支持、持仓只有一步、读取失败时标为不可分批；执行层对不可分批的持仓同样拒绝
     （fail-closed），不回落全平。

3. **换算与执行**
   - 平仓张数 = `floor(持仓步数 × 比例 ÷ 100)`，使用精确十进制换算，向下取整，不放大订单。
   - 换算结果不足一个最小步长时拒绝；比例 `100`（剩余为 0）拒绝为分批动作。
   - 平仓单为 reduce-only 市价单：平多卖出（size 为负）、平空买入（size 为正）；
     平仓张数不得超过该合约的市价单最大张数（`market_order_size_max`，未设置时按
     `order_size_max`）。
   - 成功后返回并按实际值记录：平仓张数、剩余张数、成交价、平掉的基础币数量、名义价值。
   - 取持仓失败、换算失败、下单失败、成交价不可解析时返回错误，不重试、不改走全平。

4. **提示词**
   - 动作清单、字段说明加入分批平仓；说明比例语义、系统按最小步长向下取整、过小比例会被
     拒绝、`100%` 使用全平动作、仅持仓行标注 `Partial Close: available` 时可用。
   - 中文与英文同步；输出示例包含一条分批平仓决策。
   - 持仓行包含可分批/不可分批标记；不可分批可附原因。

5. **展示与记录**
   - 决策日志记录新动作与平掉的数量、成交价；前端决策卡片能识别新动作，不落入默认 `wait`，
     并在字段存在时显示比例。
   - Gate 的成交由 OrderSync → PositionBuilder 按实际平仓数量缩减仓位，不记成全平。

6. **文档同步**
   - `docs/architecture/STRATEGY_MODULE.md` 与 `.zh-CN.md` 的动作校验清单与执行优先级清单加入
     新动作。

7. **旧语义一次性替换**
   - 不保留“只能全平”的提示词或校验口径；不新增兼容分支。

## Constraints

- 真实写操作只在 W2 授权范围内（D35）：单笔测试名义价值 ≤ 10 USDT，每一步完成后立即还原，
  不在用户手动持仓的合约上开新仓。
- 保护不变量不因分批平仓退化：W2 必须核对分批后剩余仓位的保护单仍存在（委托回读或条件单
  列表）；若交易所行为使剩余仓位失去保护，停止并回报，不在本子任务内扩展改单能力。
- 不启动 trader、不激活策略。
- 宿主机无 Go，真实接口验证脚本在 Docker 内交叉编译到 darwin/arm64 后在宿主机运行
  （容器出口 IP 不在 Gate key 白名单）；凭据只经环境变量传入，不落盘、不打印。
- Gate 接口语义以官方 API v4 文档与仓库内留档摘录为准（随单止盈止损字段、`size` 正负、
  `reduce_only`、`close=true + size=0` 全平）。

## Acceptance Criteria

- [ ] 契约解析单测：`close_long_partial`/`close_short_partial` + `close_percent` 被接受；
      `0`、负数、NaN/Inf、缺失字段、`100` 被拒；错误的 `close_percent` 指向全平动作。
- [ ] 校验在任何交易所调用前完成；`close_long`/`close_short` 旧行为不变。
- [ ] 持仓标记矩阵：17 张（步长 1）可分批；1 张不可；0.2 ETH（步长 0.1）可；0.1 ETH 不可；
      适配器未实现能力不可分批。
- [ ] 换算矩阵：17 张 50% → 8 张、剩 9；17 张 6% → 1 张、剩 16；17 张 1% → 拒绝；
      0.2 ETH 50% → 0.1 张、剩 0.1；100% → 拒绝；持仓非步长整数倍 → 拒绝。
- [ ] 下单矩阵：平多 size 为负、平空 size 为正、`reduce_only=true`、市价；超过市价单最大
      张数拒绝；成交价非正或不可解析报错。
- [ ] 执行层：不支持的适配器在发单前拒绝；部分平仓只调用分批接口，不调用全平接口；
      决策动作记录平掉的数量与成交价。
- [ ] 提示词中英均含新动作、`close_percent` 说明、100% 全平指引、仅 `available` 可用；
      持仓行含可分批/不可分批标记。
- [ ] 前端决策卡片对新动作有明确标签（不落为 wait），字段存在时显示比例；前端测试与构建通过。
- [ ] W2 真实：DOGE_USDT 随单保护开 17 张（≤10 USDT）→ 50% 分批平 8 张、剩 9 张 →
      仓位与保护单核对 → 1% 与 100% 被拒（无副作用）→ 全平 → 零残留仓位/委托/条件单；
      保存日志与证据。
- [ ] 门禁：`git diff --check`、`make test`、`make build` 通过。
- [ ] 独立检查子智能体给出 PASS；发现的问题由主会话修复并定向补验。
- [ ] 子任务提交合入父分支且父分支包含全部子提交；子任务归档；进度与父任务地图同步；
      父分支 push 留档；子 worktree 干净后删除子分支与 worktree。
