## 实测发现

1. **随单 tpsl 是委托级保护，两种列表形态并存**：开仓成交后，随单止损止盈经委托回读
   确认存在（`GetFuturesOrder` 的 `tpsl_sl_trigger_price`/`tpsl_tp_trigger_price`）；
   在未触发条件单列表（status=open）上，ETH（小数张）以 `close-long-order`（只读类型）
   出现且被 `classifyTriggerOrder` 正确分类（rule 2 止损 / rule 1 止盈，带 ID 可撤销），
   DOGE（整数张）则不出现在列表。`VerifyOrderProtection` 的双路径设计（委托回读 +
   列表补足）覆盖两种形态。
2. **对后续子任务的含义**（计划文档 10.2 的 10、11 需知）：随单 tpsl 出现在列表时
   带订单 ID，撤旧建新路径可用；不出现在列表时无法按 ID 撤销，管理路径要么在
   开仓后立即转挂仓位级条件单（`close-long-position`，H.1 实测有持仓时可创建），
   要么接受「随单保护在分批平仓与改止损场景下的局限」。子任务 11 设计时须先实测
   两种合约形态下列表的稳定性。
3. **首轮运行的两个修正**（教训，非缺陷）：ETH 目标 0.1 张的名义价值按现价恰好压在
   一步边界上，价格微动即被拒（`不足一个最小步长`）——脚本改为名义价值加 5% 裕度；
   首轮对条件单列表的强断言在发现 1 的形态下改为观察记录。
