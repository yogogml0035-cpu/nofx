# 子任务 ⑪ PRD：止损止盈管理（protective-order-management）

父任务：`11-24-gate-trading-foundation`（分支 `feat/2026_1123_gate-trading-foundation`）。
需求与决策的最终依据是计划文档 `docs/plans/2026-11-24-gate-trading-foundation.zh-CN.md`
（第 10.2 节第 11 行、D28/D31/D32/D34/D40、F10/F17/F43）。本文件只列本子任务的需求、
约束与验收标准；实施细节见 `design.md`，顺序与门禁见 `implement.md`。

## 背景

⑩ 已交付分批平仓。模型能开仓、全平、分批平，但不能修改止损止盈；持仓信息里也没有当前
止损止盈（F9），模型无法判断要不要移动。计划文档 D28 把“修改止损止盈”列入本轮范围，
D32 允许两个方向移动，D34 规定到止损价的亏损不超过本金的 2%。

本子任务的真实探针（2026-11-25，DOGE_USDT，证据见 `probe/`）确认：

- 随单止盈止损以委托级条件单 `close-long-order`/`close-short-order` 出现在未触发条件单
  列表（各 1 条），可按 ID 撤销，`is_reduce_only=true`；
- 触发价对 `order_price_round` 不对齐时，交易所接受 `tpsl_*` 字段但不创建条件单——列表为空、
  仓位实际无保护，而现行 `VerifyOrderProtection` 只读开仓委托的 `tpsl_*` 字段就会放行；
- 分批平仓后随单保护单的张数仍是开仓时的张数（reduce-only，不会反向开仓），触发价不变；
- 条件单改单接口不可用（③ research H.2：新路径 404、旧路径 code 1077），修改只能撤旧建新。

## 需求

1. **每轮读入当前止损止盈**：交易循环为每个持仓读取当前止损止盈（来自该合约未触发的条件单，
   按 `order_type` 与 `trigger.rule` 判定方向与类型），写入持仓信息；模型在提示词里能看到
   每个持仓的当前止损价、止盈价，或明确的“未知”标记。
2. **决策契约新增修改动作**：`update_stop_loss`、`update_take_profit`，价格字段复用
   `stop_loss` / `take_profit`；模型只给出标的与新价格。
3. **合法性校验**（决策解析时）：
   - 目标持仓必须存在，且当前止损止盈可读（未知时拒绝修改，不能保证旧保护被替换）；
   - 新价格必须是有限正数，位于现价的正确一侧（多：止损低于现价、止盈高于现价；空相反）；
   - 止损：`|持仓数量| × |入场价 − 新止损价| ≤ 本金 × 2%`（D34；本金不含浮盈）；
   - 止盈：无亏损上限，但仍须在现价正确一侧；
   - 动作与价格字段匹配（`update_stop_loss` 只读 `stop_loss`，`update_take_profit` 只读 `take_profit`）。
4. **改单执行**：撤旧建新。适配器负责：读取当前保护、按合约价格步长对齐新价格、挂新的仓位级
   保护单、核对新单存在、撤销旧单、核对旧单不存在；失败时恢复原保护（撤销新单），保证任何
   时刻仓位都有同类型的保护单。执行路径 fail-closed：适配器不具备保护单管理能力、持仓不
   存在、当前保护未知、换算或校验失败时，不发出任何请求。
5. **修改止损的亏损上限**（D34、F17）：执行路径用交易所最新持仓（数量、入场价）与本金复核
   上限，超过即拒绝；不依赖决策解析时的旧快照。
6. **价格步长对齐**（探针发现，属保护不变量）：随单止盈止损与仓位级保护单的触发价必须对齐
   `order_price_round`。开仓路径按“止损向现价收紧、止盈远离现价”对齐，对齐后仍在现价正确
   一侧才提交；对齐后的实际价格回报给交易路径记录。
7. **保护核对收紧**：`VerifyOrderProtection` 以未触发条件单列表为准（同侧止损与止盈各至少
   1 条），开仓委托的 `tpsl_*` 字段只作旁证；列表缺失即失败（调用方立即平仓）。持仓已不存在
   时视为无需保护。
8. **提示词与前端**：中英提示词新增两个动作的说明与示例；前端决策卡片识别两个动作并展示
   新价格；架构文档与规范同步。
9. **旧语义一次性替换**：不保留兼容分支；`SetStopLoss`/`SetTakeProfit` 维持“不支持”的
   明确错误；不改 ⑩ 的分批平仓语义（随单保护单 reduce-only，继续覆盖剩余仓位）。

## 非目标

- 不实现止盈止损的独立挂单（`types.Trader` 的旧方法继续报错）。
- 不改变回撤监控、开仓金额计算、分批平仓比例契约。
- 不触发真实止损止盈做“是否反向开仓”的实盘实验；探针已证明随单保护单 reduce-only。
- 不引入新的条件单类型（计划级 `plan-close-*`）作为 NOFX 自己创建的形态。

## 约束

- 不启动 trader、不激活策略；真实写操作沿用 D35 授权：单笔名义价值 ≤ 10 USDT，完成即还原。
- Gate 接口开发前读官方文档与已留档摘录（③ research、⑩ probe）；文档站不可达时以 SDK
  v7.2.184 模型注释与本子任务真实探针为准，并留档。
- 能力接口放在 `trader/types`，Gate 概念不进入 `kernel` 与通用交易路径。
- 父分支不得出现“持仓存在但没有有效止损”的状态：改单过程先挂新、核对后再撤旧。

## 验收标准

1. 单测覆盖：触发价对齐矩阵（多空 × 止损止盈 × 对齐方向 × 边界）、保护读取归类
   （委托级/仓位级/重复/未知）、改单执行顺序与失败恢复、决策契约校验矩阵（未知保护、方向、
   2% 上限、字段匹配）、持仓信息与提示词标记、执行路径 fail-closed。
2. 真实 W2（DOGE_USDT，17 张随单保护）：开仓后列表有同侧 SL+TP → 分批 50% → 改止损
   （向收紧方向）→ 改止盈（向现价方向，D32 双向）→ 列表各 1 条且为新价、旧单不存在 →
   全平 → 零持仓、零条件单、零挂单，仓位设置与可用余额差仅手续费。
3. 真实 W3 级（ETH_USDT，0.1 张）：开仓后列表可见委托级 SL+TP；改止损一次并核对；全平零残留。
4. `git diff --check`、`make test`、`make build` 全部通过；独立检查子智能体 PASS。
